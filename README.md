# 短链接 · Cloudflare 网页部署版



## 一、创建 D1 数据库

1. 登录 https://dash.cloudflare.com/
2. 在侧栏找到 **Storage & databases → D1 SQL Database**（中文界面名称可能不同）。
3. 点击创建数据库，名称例如 `short-commands`，创建完成。
4. 不用手动建表，第一次访问管理 API 时程序会自动建表。

## 二、创建 Worker 并粘贴代码

1. 打开 **Workers & Pages → Create application / 创建应用**。
2. 选择创建 Worker / Hello World，名称例如 `short-commands`，点击部署。
3. 打开该 Worker 的 **Edit code / 编辑代码**。
4. 用文本编辑器打开本包的 `worker.js`，复制全部内容，替换默认入口文件内容。保留文件名 `worker.js` 或控制台默认的 `index.js` 均可。
5. 点击 **Deploy / 部署**。程序只需要这一份代码，没有额外文件或构建步骤。

## 三、绑定数据库

1. 进入该 Worker 的 **Bindings / 绑定**（部分界面在 Settings 下）。
2. 点击 **Add binding → D1 database**。
3. Variable name / 变量名填 **DB**，必须大写且完全一致。
4. 选择刚创建的 `short-commands` 数据库，保存；若页面提示部署，完成部署。

## 四、设置管理员账号和密码

在 Worker 的 **Settings → Variables and Secrets → Add** 添加以下三项：

| 变量名 | 类型 | 值 |
|---|---|---|
| ADMIN_USER | Text / 文本 | 自己设置的管理员账号 |
| ADMIN_PASSWORD | Secret / 密钥 | 自己设置的密码，至少12位，建议随机密码 |
| SESSION_SECRET | Secret / 密钥 | 独立随机字符串，至少32位，建议密码管理器生成64位 |

不要使用本说明中的字面示例作为密码。变量设置完成后保存并部署。首次初始化时账号与密码存入 D1，密码以加盐 PBKDF2 哈希保存。

后台修改账号密码后，数据库内的新值生效；环境变量只是首次初始化值，不会覆盖新密码。请保留三项环境变量。SESSION_SECRET 修改后旧登录会话失效。账号密码修改和退出登录均使全部会话失效。

## 五、绑定域名

建议使用单独子域名，例如 `cmd.你的域名`，避免覆盖现有网站。

1. 确保域名已经在当前 Cloudflare 账户中完成接入。
2. 在 Worker 中打开 **Settings → Domains & Routes → Add → Custom Domain**（部分新界面为 Domains）。
3. 输入你的子域名并保存，等待证书和域名状态正常。
4. 浏览器打开 `https://cmd.你的域名/admin`，使用第四步的账号密码登录。

也可以先通过 Worker 的 HTTPS workers.dev 地址测试。生成短命令时使用你当前打开后台的域名，因此正式发布前请从正式自定义域名登录。

## 六、添加第一条命令

1. 点击“添加命令”。
2. 名称填“示例安装”，短路径填 `demo` 或 `tools/demo`，不用输入域名和开头斜线。
3. 内容模式选择“原始命令 · 跟随源站”。
4. 粘贴完整原始命令，例如 `bash <(curl -fsSL https://raw.githubusercontent.com/owner/repo/main/install.sh)`。示例 URL 是占位值，必须替换成真实地址。
5. 原始命令需要 Bash 时选择 bash；只有确认脚本兼容 POSIX Shell 时才选 sh。
6. 保存后即可复制短命令。

安全的首次测试内容可以填：

```bash
printf '短命令服务正常\n'
```

命令将生成两种格式：

```bash
bash <(curl -fsSL https://cmd.你的域名/demo)
curl -fsSL https://cmd.你的域名/demo | bash
```

第一种格式要求调用它的当前 Shell 支持进程替换（如 Bash）。第二种更短且适合许多非 Bash 的调用环境，但被执行脚本如需交互输入，可能需要自行从 `/dev/tty` 读取。菜单安装脚本建议使用第一种格式。

Cloudflare 返回保存的命令文本，执行发生在调用者的设备。原始命令原样保留，支持多行，不会自动重写安装逻辑，也不会自动验证安装脚本在所有系统上的可运行性。公开短地址不需要登录；不要在命令内容中保存私密令牌。

### 固定副本

选择“固定副本”，粘贴完整脚本源码。平台保存该副本，不自动向 GitHub 拉取或同步。执行时由选择的 bash/sh 解释，保存内容的第一行 shebang 会被移除。脚本内部引用的其他下载地址仍依赖对应源站。

### 参数

如果原始命令本来带参数，将参数一并粘贴保存。此版不提供向短命令动态传参；需要不同参数可分别保存不同短路径。

## 七、管理、长期保存和备份

- 编辑内容保留路径，旧短命令继续指向更新后的内容。响应设置 no-store，不主动缓存旧命令。
- 修改短路径后旧地址不再有效，程序会显示提示。建议发布后保持路径稳定。
- 禁用和删除返回 HTTP 404；curl 使用 -f 会报告失败。
- 名称、路径、备注均可搜索。短路径区分大小写。
- 数据保存在 D1，不设置到期日期，不自动删除。更新程序时保持原 DB 绑定。
- 域名、Worker、数据库和账户需持续正常，访问也受 Cloudflare 套餐配额约束，不能仅凭域名续费保证永远可执行。
- 点击“导出备份”下载全部命令，不包含账号密码。导入只增加记录，不覆盖现有路径；如有冲突，整批回滚。
- 单条内容上限200KB，单次导入上限1000条、2.5MB；总记录数受 D1 存储及套餐额度限制。
- 部署代码升级前导出备份，不要删除数据库。

## 八、常见问题

**页面能打开，登录提示配置未完成**：检查 DB 大小写、绑定数据库、三项变量以及密码长度。确认保存并部署。

**首次访问短地址提示先登录后台**：先从后台登录，完成自动初始化并添加记录。

**忘记账号密码**：在 D1 数据库的 Console 执行 `DELETE FROM admin WHERE id=1;`，在 Worker 中设置新的 ADMIN_USER、ADMIN_PASSWORD，并重新部署代码以重启初始化状态，然后打开后台登录。不会删除 commands 表和已保存命令。旧会话的失效由新盐与重设 SESSION_SECRET 保证：重置时同时更换 SESSION_SECRET。

**curl 返回 HTML 验证页面**：检查是否给短地址开启 Cloudflare Access、验证码或交互挑战。这些机制会妨碍终端读取脚本；不要对公开短命令路径使用交互验证。管理 API 自带登录和来源校验。

**访问旧域名后生成的仍是旧域名**：从新的正式域名打开后台后重新复制。路径映射本身没有绑定固定域名。

**无法安装原 GitHub 项目**：此工具负责提供命令，不替代项目依赖安装，也不会自动缓存原命令下载的所有文件。检查原始命令和调用设备网络。
